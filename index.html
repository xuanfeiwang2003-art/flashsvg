01 / ABSTRACT

Abstract

Language-model SVG generators are slow, and many of their drawings never finish: they decode one coordinate token per forward pass and often never emit an end-of-sequence token, running to the length cap while the truncated programs still render and pass validity-filtered evaluation. We show that termination, not syntax, is the main failure of the released OmniSVG models.

Termination-aware post-training teaches a model to end its drawings instead of running to the cap, learning from its own rendered candidates, with non-terminating ones as preference negatives and no external judge; it also improves StarVector-8B and Qwen3.8-27B.

FlashSVG, to our knowledge the first SVG generator trained with a block-diffusion objective over SVG tokens, drafts several tokens per forward pass and verifies them with the same weights, so committed tokens follow the model's own autoregressive distribution up to floating-point rounding; faithfulness comes from training, speed from drafting.

On MMSVG-Bench image-to-SVG, FlashSVG reconstructs icons and illustrations more faithfully than the released OmniSVG-4B on every fidelity metric we report, and 99.7% / 98.2% of its candidates terminate. On one GPU at batch 1 and on the same engine, icon latency falls from 3.1 s for the released model to 1.4 s with post-training and to 0.7 s with verified decoding. The pixel tracer vtracer remains more faithful and faster on these clean renders, and the strongest API models more faithful; text-to-SVG remains weak.

SCOPE & LIMITATIONS

Faster generation.
Measured claims.

Frontier API models and non-learned vectorizers remain more faithful on these clean renders. Text-to-SVG is still a weak task, and complex scenes often exceed the token budget. Verified decoding’s advantage shrinks at larger batch sizes.

Some design decisions were informed by MMSVG-Bench; it is not a fully held-out benchmark. Refer to the paper for evaluation details, ablations, statistical uncertainty and additional limitations.
